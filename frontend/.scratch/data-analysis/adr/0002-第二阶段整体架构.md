# 第二阶段整体架构：本地伪分布式 Hadoop + 两层 Hive + CSV 中转

第二阶段电商数据分析项目采用本地伪分布式 Hadoop/Hive，Hive 仅分 ODS（原始落地）和 ADS（应用结果）两层，Hive 结果通过导出 CSV 由 Java 程序写入 MySQL，整体流程手动分步执行。

## 考虑过的选项

- **真集群 Hadoop**：数据量仅 10 万级行为日志，真集群无性能收益，部署成本高，拒绝。
- **Hive 四层分层（ODS/DWD/DWS/ADS）**：课程作业无数据复用需求，多两层仅增加 SQL 编写量，不加分，拒绝。
- **Sqoop 导出 Hive→MySQL**：需额外安装配置 Sqoop，课程未要求，CSV 中转已足够，拒绝。
- **一键脚本自动执行全流程**：课程答辩需分步演示每一步输出，手动分步更适合教学场景，拒绝。

## 决策

1. Hadoop/Hive 运行在本地伪分布式模式
2. Hive 两层架构：`ods_`（4 张原始表）+ `ads_`（4 张结果宽表）
3. Hive→MySQL 采用 CSV 中转：Hive 导出 CSV → Java 读 CSV → 写 MySQL
4. 全流程手动分步执行，每步有明确可验证的输出

## 后果

- 数据量上限受单机资源约束，但 10 万级绰绰有余
- 手动分步意味着答辩时需依次执行 5 步，但每步结果可单独展示
- CSV 中转需注意编码（UTF-8）和字段分隔符（默认 \t，导出时指定逗号）
