# MySQL 落地采用每模块一张宽表，全量覆盖写入

Hive ADS 层的 4 张结果表落地到 MySQL 时，每个分析模块对应一张宽表，包含该模块所有可视化指标，采用全量覆盖（TRUNCATE + INSERT）方式写入。

## 考虑过的选项

- **星型模型（事实表 + 维度表）**：课程作业无多维分析/下钻需求，星型模型增加 JOIN 复杂度，前端接口查询慢，拒绝。
- **增量写入**：数据为模拟生成，每次全量重新生成，增量无意义，拒绝。
- **Hive 直接查询不落地 MySQL**：课程要求 MySQL 落地 + SpringBoot 接口，必须经过 MySQL，拒绝。

## 决策

1. 4 张 MySQL 宽表：`ads_user_behavior`、`ads_order_analysis`、`ads_review_analysis`、`ads_chat_analysis`
2. 每张表包含该模块全部图表所需指标，按查询维度（如日期、品类）冗余存储
3. 写入方式：每次运行先 TRUNCATE 表，再批量 INSERT（全量覆盖）
4. Java 落地程序读取 Hive 导出的 CSV，JDBC 批量写入 MySQL

## 后果

- 表结构可能较宽（10-20 列），但查询单表即可出图，接口开发简单
- 全量覆盖意味着每次重新生成数据后旧数据被替换，符合模拟数据场景
- 若后续需要历史趋势对比，需增加日期分区或快照表（当前不需要）
