**踩坑记录（重要，避免重复踩坑）**：

1. **国内 Docker Hub 访问超时**：需配置镜像加速器。可用镜像源：`https://docker.1panel.live`（已验证可用）。中科大/网易/腾讯等公共镜像源已失效。配置文件：`C:\Users\Administrator\.docker\daemon.json`

2. **postgres:9.5.3 镜像层不完整**：拉取时特定层解压失败，换 `postgres:9.6` 解决。

3. **postgres:13 与 Hive 2.3.2 不兼容**：Hive Metastore schema 验证失败，反复重启。换 `postgres:9.6` 解决（Hive 2.3.2 官方支持 PostgreSQL 9.x）。

4. **Hive Metastore schema 未自动初始化**：环境变量 `HIVE_CORE_CONF_datanucleus_schema_autoCreateAll=true` 未生效，schematool 默认用 Derby 导致初始化脚本语法错误。**解决方案**：挂载自定义 `hive-site.xml` 到 `/opt/hive/conf/hive-site.xml`，在其中显式配置 PostgreSQL 连接和 `datanucleus.schema.autoCreateAll=true`。

5. **HiveServer2 连接 HDFS 失败**：bde2020 镜像启动脚本自动设置 `fs.defaultFS=hdfs://自己的hostname:8020`，覆盖了 hadoop.env 配置，导致连接 NameNode 被拒。**解决方案**：在自定义 `hive-site.xml` 中显式设置 `fs.defaultFS=hdfs://namenode:9000`。

6. **beeline 连接报 `Missing version in readMessageBegin, old client?`**：认证方式不匹配。**解决方案**：beeline URL 中必须加 `;auth=noSasl`，即 `jdbc:hive2://localhost:10000/;auth=noSasl`。

7. **Docker 数据迁移到 F 盘**：Docker Desktop 默认数据存 C 盘 WSL2 虚拟磁盘。迁移方法：停止 Docker → `wsl --export docker-desktop-data F:\docker-data\docker-desktop-data.tar` → `wsl --unregister docker-desktop-data` → `wsl --import docker-desktop-data F:\docker-data\data F:\docker-data\docker-desktop-data.tar --version 2` → 删除 tar → 重启 Docker。

8. **docker.exe 不在 PATH**：Docker Desktop 安装后 `docker` 命令不在系统 PATH，需用完整路径 `C:\Program Files\Docker\Docker\resources\bin\docker.exe`，或在每次 PowerShell 会话中 `$env:Path += ";C:\Program Files\Docker\Docker\resources\bin"`。

### 6. metastore 从 PostgreSQL 迁移到 Derby（重大架构变更，2026-09-16）

> **背景**：Docker Desktop 重启后，PostgreSQL metastore 出现严重兼容性问题，导致 Hive 建表操作卡住（10分钟+超时），无法继续推进。经过多轮排查，最终决定将 metastore 存储后端从 PostgreSQL 切换为 Derby 内嵌数据库。

#### 问题根因

1. **`pg_am.amcanorder` 列缺失**：PostgreSQL 9.6.24 实例的 `pg_am` 系统表只有 3 列（amname/amhandler/amtype），缺少 `amcanorder` 列。Hive 2.3.2 自带的旧 JDBC 驱动（postgresql-9.4.1208.jre7.jar）在 DataNucleus 验证表索引时查询该列，报 `PSQLException: column am.amcanorder does not exist`。
2. **替换驱动后建表仍卡住**：将驱动升级为 postgresql-42.4.3.jar 后，metastore 启动不再报错，但 `CREATE TABLE` 操作在 DataNucleus 持久化表元数据时无限卡住（10分钟+无响应），TBLS 表始终为空。
3. **重置 schema 无效**：多次 DROP SCHEMA + 重新初始化，问题依旧。

#### 最终方案：切换到 Derby 内嵌数据库

**修改文件**：
- `docker-hive/hive-site.xml`：
  - `javax.jdo.option.ConnectionURL` → `jdbc:derby:;databaseName=/opt/hive/metastore_db;create=true`
  - `javax.jdo.option.ConnectionDriverName` → `org.apache.derby.jdbc.EmbeddedDriver`
  - 删除 `ConnectionUserName` / `ConnectionPassword` / `hive.metastore.uris`（使用内嵌 metastore，无需独立 metastore 服务）
- `docker-hive/docker-compose.yml`：
  - hive-server 的 `SERVICE_PRECONDITION` 移除 `hive-metastore:9083`（不再依赖独立 metastore 容器）

**容器变更**：
- `hive-server`：继续运行，使用内嵌 Derby metastore（首次启动自动创建 schema）
- `hive-metastore`：**不再需要启动**（保留容器但不启动）
- `hive-metastore-postgresql`：**不再需要启动**（保留容器但不启动）

**效果**：
- 建表从"卡住10分钟+"变为"0.2秒成功"
- HiveServer2 连接正常，所有 SQL 操作正常
- Derby 数据文件存储在 hive-server 容器内 `/opt/hive/metastore_db/`

#### 注意事项

1. **Derby 内嵌模式只支持单连接**：当前只有 hive-server 一个客户端连接，足够使用。如果后续需要多客户端同时连接 metastore，需切换到 Derby Network Server 模式。
2. **Derby 数据已持久化到 named volume**（2026-09-16 Code Review 修复）：`/opt/hive/metastore_db` 已挂载为 `hive-metastore-db` volume，`--force-recreate` 后数据保留，无需重新建表。
   - **踩坑记录**：首次挂载 volume 时 Docker 预创建空目录，Derby `create=true` 报 `XBM0J: Directory already exists`。解决方法：用临时容器初始化干净 Derby 数据后拷入 volume。
   - **启动注意**：`docker compose restart hive-server` 后首次启动较慢（约50秒），属正常现象。
3. **hive-metastore 和 PostgreSQL 容器保留但不启动**：如果后续需要切回 PostgreSQL，修改 hive-site.xml 即可，但需先解决 amcanorder 兼容性问题。
4. **启动命令**：只需启动 Hadoop 4容器 + hive-server，共5个容器：
   ```bash
   cd E:\space\Project\test\mall-sys\docker-hive
   docker compose up -d namenode datanode resourcemanager nodemanager hive-server
   ```
5. **禁止 `docker compose down -v`**：会删除所有 named volume，包括 Derby 数据（hive-metastore-db）和 HDFS 数据（hadoop_namenode/hadoop_datanode）。
